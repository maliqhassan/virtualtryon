# Frontend Architecture

Expo (SDK 54) + React Native + TypeScript, using Expo Router for navigation.

## Folder structure

```
frontend/
├── src/app/          # Expo Router routes only — thin, no business logic
├── src/components/   # Shared, presentational, reusable UI
├── src/features/     # Feature modules (screens' supporting components,
│                      hooks, API calls, Zustand slice — colocated)
├── src/hooks/         # Cross-feature custom hooks
├── src/services/api/  # Axios client + (future) endpoint definitions
├── src/lib/            # Third-party client instances (TanStack Query client)
├── src/store/          # Global Zustand stores
├── src/constants/      # Env access, design tokens
└── src/types/          # Cross-feature TypeScript types
```

`app/` stays route-only so navigation structure doesn't get tangled with
component logic — a route file imports from `features/` or `components/`,
it doesn't define large components inline.

## State management: three layers, not one

- **Server state** (anything that came from the API) → TanStack Query. Never
  mirror server data into Zustand; that's a stale-cache bug waiting to happen.
- **Global client state** (things multiple unrelated screens need, e.g. an
  in-progress try-on session) → Zustand.
- **Local UI state** (a form's current value, a toggle) → `useState`/React
  Hook Form. Don't promote this to Zustand by default.

## Styling

NativeWind (Tailwind for React Native) via `className`. Avoid
`StyleSheet.create` unless a style genuinely can't be expressed as a utility
class (e.g. a value computed at runtime from a shared value in Reanimated).

## Path aliases

`@/*` → `src/*`, `@/assets/*` → `frontend/assets/*` (configured in
`tsconfig.json`, generated by Expo's default template — kept as-is).

## Forms & validation

React Hook Form for form state, Zod for schema validation, wired together via
`@hookform/resolvers`. Validate at the boundary (form submit, API response
parsing) — not everywhere.
